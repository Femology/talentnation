# 2.1.3 — Dynamic typing and developer velocity

**Status:** Covered

**One-line takeaway:** Python names can refer to objects of different types, but operations still enforce type rules.

## Study notes

```text
x -> 42         (int)
x -> "now"      (str)
x -> [1, 2, 3]  (list)
```

A data type describes a value: integer (25), float (3.14), string ("Ada"), boolean (True), list ([1,2,3]). Python is dynamically typed; the object has a type but a name is not permanently tied to it. Static typing checks type constraints before execution and can infer types without explicit declarations.

```python
age = "25"
print(int(age) + 1)  # 26
print("I am " + str(25))
```

"5" + 5 raises TypeError; int("banana") raises ValueError. Python is often described as strongly typed, although the term has no single formal definition. Dynamic typing can help rapid prototyping but moves some errors into runtime. Use testing, validation and optional type hints.

```python
def add(a: int, b: int) -> int:
    return a + b
```

Type hints are not automatically enforced by Python; mypy and Pyright can check them.

**Vocabulary:** type, dynamic typing, static typing, type conversion, runtime error, type hint, refactoring, developer velocity.
