# 2.1.5 — Execution speed vs implementation speed

**Status:** Covered

**One-line takeaway:** Choose technology based on requirements, development cost and measured performance rather than raw speed alone.

## Study notes

Execution time is how long the program takes; implementation speed is how fast engineers build it. Illustrative example: Python project takes two weeks and serves an order in 0.5s; C++ project takes eight weeks and serves it in 0.08s. If the requirement is under 1s, both meet it. These are not benchmarks.

```text
Request -> network -> application -> database -> response
                       20ms          800ms
```

Find the bottleneck before optimizing. Profiling measures resource use by code sections; benchmarking measures performance under defined conditions.

```python
from time import perf_counter
start = perf_counter()
sum(range(1_000_000))
print(perf_counter() - start)
```

This measures elapsed wall-clock time, not only CPU time. Use timeit for repeatable small benchmarks. Language bindings let Python call optimized native libraries. Latency is delay per request; throughput is work per unit time; bandwidth is link capacity. A 100 Mbps link may achieve 60 Mbps throughput and 80 ms latency (illustrative).

Choose Python for many prototypes, AI and network-heavy services; native languages may be more appropriate for strict real-time or hardware-sensitive workloads. Hardware costs, engineering time, reliability and maintainability matter.

**Vocabulary:** execution time, implementation speed, developer velocity, binding, bottleneck, profiling, benchmark, optimization, latency, throughput, bandwidth, trade-off, scalability.
