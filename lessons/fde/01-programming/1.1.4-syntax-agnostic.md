# 1.1.4 — Syntax-agnostic mindset

**Status:** Covered; assessment deferred

**One-line takeaway:** Design correct logic before translating it into a programming language.

## Study notes

Syntax is grammar; semantics is what instructions mean; pseudocode is a structured language-independent plan.

```text
IF patient is not verified
    request verification
ELSE IF days ahead < 5
    offer a later date
ELSE
    proceed to availability check
```

```python
def check_eligibility(verified, days):
    if not verified:
        return "Verify identity"
    if days < 5:
        return "Choose later date"
    return "Check availability"
```

```javascript
function checkEligibility(verified, days) {
  if (!verified) return "Verify identity";
  if (days < 5) return "Choose later date";
  return "Check availability";
}
```

The intended rule is the same. Languages differ in type systems, numerical behavior, concurrency and libraries, so porting can require more than changing syntax. Valid syntax can encode unsafe logic. Plan goal, inputs, outputs, ordered operations, conditions, failures and verification.

**Vocabulary:** syntax, semantics, pseudocode, implementation, computational thinking.

**Communication technique:** PREP = Point, Reason, Example, Point; use clear connectors (because, however, for example, therefore). Speaking and long assessments deferred until the learner chooses to resume.
