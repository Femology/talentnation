## Study notes

A calculator follows rules, not intentions. A repeated ATM request can produce a different outcome when the account balance has changed.

```text
Input + starting state + instructions -> execution -> result
```

```python
def withdraw(balance, amount, pin_correct):
    if not pin_correct or amount <= 0 or amount > balance:
        return balance, "Rejected"
    return balance - amount, "Approved"

print(withdraw(20000, 5000, True))  # (15000, 'Approved')
```

A program can repeatedly produce an incorrect answer if its logic is wrong. Not every real system is deterministic: randomness, concurrent operations, timing and external inputs can affect outcomes.

### FDE application: payment timeout
A timeout only means a response was not received in time. A transfer might already have succeeded. A balance alone is insufficient evidence because it may be stale or affected by other transactions. Save a unique operation identity before submission, use a provider-supported idempotency key, mark uncertain outcomes UNKNOWN, and query the specific authoritative transaction record. Retry only when the provider's contract makes it safe; otherwise reconcile or escalate. A repeated request may return the original response or pending status, not necessarily a duplicate error.
