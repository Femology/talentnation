# 3.1.5 — Headless execution

**Status:** Covered

**One-line takeaway:** Run and inspect programs without a graphical interface, including on remote servers.

## Study notes

```text
Laptop -> SSH -> remote shell -> Python script -> stdout / stderr
                                             -> exit status
```

```bash
# Use a new practice directory: > overwrites files.
mkdir -p headless_demo && cd headless_demo
printf 'print("System Online")\n' > core.py
python3 core.py
echo $?
```

Expected output: System Online, then 0. A nonzero status usually signals failure or a special condition. Check $? immediately. Headless does not mean background or always running.

| Stream or operator | Meaning |
|---|---|
| stdin | Standard input |
| stdout | Normal output |
| stderr | Diagnostics/errors |
| > | Overwrite output file |
| >> | Append output |
| 2> | Redirect stderr |
| $? | Last foreground command/pipeline exit status |

python3 core.py > output.txt 2> error.txt separates logs. Python REPL uses >>> and exit() returns to Bash. Script mode runs a saved file; unsaved edits are not read. Paths and case matter.

A background command (&) may stop on SSH disconnect; production services need supervision, e.g. systemd or container restart policies. Some headless services run continuously; a simple script exits. Exit status 0 does not independently verify a real business outcome.

**Vocabulary:** headless, GUI, SSH, script, streams, redirection, exit code, REPL, logging, foreground/background, process manager, CI/CD.
